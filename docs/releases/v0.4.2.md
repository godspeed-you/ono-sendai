# Ono-Sendai v0.4.2 — a package can be a provider

A patch release on top of v0.4.1. Nothing here changes the shell a user types into, and no new
specification tranche is implemented. What it adds is the last stretch of the KUANG/11 extension
contract: the generic boundaries a loaded package needs before it can present an external system
as typed resources, relationships, places and bounded actions — the same way the first-party Linux,
network, systemd and container providers already do. Every one of them is provider-neutral, and a
first external-system provider now exercises them end to end.

> Ono is the deck. KUANG/11 is the software you load into it.

## A loaded package is a provider

- **A contributed target is queried, not invoked.** A package that contributes a target answers
  `get <word>` through `provider.query`, with a declared schema, a stable identity and host-stamped
  provenance — the same contract a native provider answers, rather than an untyped command return.
- **A contributed target is a kind of place, and a contributed relation runs between two of them.**
  `enter`, `near` and `follow` reach a package's objects, and a shape declared `<from>-><to>` in the
  manifest registers a relation the shell can walk — filtered by capability before it is merged into
  a map, so a package without `relation.write` contributes nothing rather than a phantom edge.
- **A package answers more than one invocation at once.** An invocation gets a worker of its own,
  responses are routed by sequence, and beyond a declared ceiling the answer is an explicit
  concurrency limit rather than a quarantine. The ceiling is declared twice — by the author in code
  and by the operator in the manifest — and the smaller wins.
- **A contribution declares its own arguments and its own refusal**, so a shell can complete and
  explain a package's options before the package has run, and a refusal reaches the caller as a
  failure rather than as an empty success.
- **A contributed target says whether its answer ends**, which is what lets a watch reach the shell
  as a live stream rather than as a table that never arrives.
- **A package's own audit record joins the trail the broker writes**, under host attribution and a
  host clock, so a package cannot forge either.

## The provider action contract

- **`provider.mutate` is a capability of its own**, distinct from reaching a system: a package that
  may read an external system cannot change it without a separate grant the host checks at every
  invocation. A provider action declares its accepted target types, that it mutates, its idempotency
  and how its outcome is verified, where the host reads them before any package code runs.
- **A contributed kind of place declares its semantic roles and the kind above it**, so `find place
  --role` reaches it across kinds and `up` follows the containment the package contributes.
- **The provider error taxonomy** gains the codes an external-system provider needs to stay honest:
  an answer that is inconclusive rather than absent, an authentication failure distinct from an
  authorization denial, and a rate-limited response.
- **Load-time schema validation, host-resolved `~` in a path scope, and a handshake-only target
  named for what it is** close the remaining gaps between what a package declares and what the host
  can check before it runs.

## A first external-system provider

The Kubernetes reference provider is built, in its own repository,
[ono-sendai-kubernetes](https://github.com/godspeed-you/ono-sendai-kubernetes). It reads any kind a
cluster serves, walks relationships with inspectable evidence, navigates the spatial model, and
makes bounded changes — using only the generic contract above, with **zero Kubernetes concepts in
Ono core**. It passes its own specification's fourteen acceptance gates against `kind` at v1.35,
v1.36 and v1.37, with no `kubectl` in the path. It is the evidence that the KUANG/11 external-system
architecture generalises beyond the first-party providers, and it ships no release of its own yet.

## Documentation

The `docs/` tree separates strategy, architecture, specification and contract so the four kinds of
document no longer share a directory name, and the cross-repository links to the Kubernetes provider
resolve.

## Notes for upgrading

There is nothing to do. `v0.4.2` is source- and behaviour-compatible with `v0.4.1` for anyone using
the shell; the additions are contracts a package author consumes, not changes a user sees. The
plugin manifest format, the capability set and the command surface are unchanged.

## Install

The `.deb` and `.rpm` for both architectures are on the release page. To install and make it your
login shell as an unprivileged user:

```bash
sudo apt install ./ono_0.4.2_amd64.deb          # or ono_0.4.2_arm64.deb
sudo dnf install ./ono-0.4.2-1.x86_64.rpm       # or ono-0.4.2-1.aarch64.rpm

chsh -s /usr/bin/ono                             # make it your login shell
```

Verify before you install — the sequence is in `docs/reference/release-verification.md` and in the
README, and it is the one `scripts/verify-release.sh` runs, byte for byte:

```bash
sha256sum -c SHA256SUMS --ignore-missing
cosign verify-blob SHA256SUMS --signature SHA256SUMS.sig --certificate SHA256SUMS.pem \
  --certificate-identity-regexp '^https://github\.com/godspeed-you/ono-sendai/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Or build it: `cargo build --release -p ono-cli`. See the README for configuration, the plugin
layout and login-shell setup.
