# Ono-Sendai v0.6.5 — KUANG/11 ecosystem stabilization

A stabilization release on top of v0.6.4. It makes the extension model keep the promises the host
already made about it: a background job runs a package in the session's one instance and every
instance ends with an unload in the trail, a destructive plugin command is confirmed exactly as a
core one is, a package's declared risk can no longer sit below its capabilities, an invocation's
stream carries its whole answer, a view belongs to its own invocation, contributed places keep
their pins and sit in the scope their package declares, a contributed relation has a name and a
cost and may lead into another package's kind of place, a bounded contributed answer streams, and
the three host services that answered `provider.unavailable` either serve or say exactly why they
do not. The GitHub milestone `v0.6.5` ("KUANG/11 Ecosystem Stabilization") is the release
inventory — 13 issues, as ADR-0862 and ADR-0929 established for the releases before it. Nothing
else rode along: no dependency moved, and wasmtime stays at 48.0.8.

> Stabilize the extension model — KUANG/11 plugins, contributed providers and their
> conformance — once the core provider and spatial abstractions are reliable.

Every issue of the milestone is met, all 13 of them. Three are met in a form an ADR records:
#156 in the form ADR-1001 chose, #203 with `secrets.request` declined by ADR-1016 for a recorded
reason, and #224 in all seven of its parts, with the subscribe half of its sixth part rejected by
ADR-0588 and made explicit by ADR-1013 (*Deferred and not met*, below).

## Security and compatibility: a destructive plugin command needs `--confirm`

> **A contributed command declared `risk: destructive` now needs `--confirm` on every run** — in a
> script, in a background job and at a terminal alike, exactly as a core `confirmation: always`
> command such as `protect` or `stop socket` does. Without it the command is refused with
> `safety.confirmation_required` before the package is loaded or sent anything, and the help line
> names the spelling to write. Nothing prompts: a plugin's destructive command behaves as Ono's own
> (ADR-1001). The Kubernetes provider's `remove k8s-resource` is such a command, so even its
> default server dry run now reads
> `remove k8s-resource --context prod --kind ConfigMap --name stale --confirm`.
>
> **`get plugin` answers `ono.plugin/2`**, which no longer carries `isolation`; `execution_tier`
> is the one field naming what an instance runs in (ADR-0996). A script that selects `isolation`
> gets a missing field. `docs/MIGRATION.md` §15 lists every change.

Before this release a package's declared risk was decoration. A command needing a `mutate` or
`destructive` capability could declare no risk at all, and a `destructive` one ran without a
word (#156). Now:

- **A mutating command declares its risk, never below its capabilities.** At registration the
  host computes the highest risk among the capabilities a command declares; a command that needs
  a `mutate` or `destructive` capability and declares no `risk:`, or a lower one, is
  `package.invalid`, reported by `get plugin` and absent from `get command`, `help` and
  completion (ADR-1000, K11P §6.6).
- **The running package cannot argue its way around it.** A command the package declares in its
  startup hello is held to the same floor when it is invoked (ADR-1002), and where a command is
  declared on disk and in the hello, the stronger of the two decides the confirmation (ADR-1022).
- **A destructive capability belongs to the command that declared it.** The broker refuses a host
  call needing a `destructive` family (`recovery.restore` today; `filesystem.write` once it has a
  host call) with `capability.denied`, `reason: undeclared-by-command`, unless every invocation
  open in the instance is a command that declared it (ADR-1022).
- **`--confirm` is a flag wherever it is written.** `remove echo-record --confirm r1` confirms and
  leaves `r1` to the selector, as the core binder reads a flag; `--dry_run false` keeps its
  meaning (19670ee0, case 163).
- **A just-in-time question is the invoking evaluator's to ask.** A job never prints a permission
  question at the shell's prompt or reads the keystrokes meant for it; the foreground at a
  terminal is asked, whoever loaded the instance, and an invocation that waited for a slot is
  still asked through its own evaluator (ADR-1023, f426679e).

## A job runs packages in the session's instances

- **One host per session knows every instance.** A package command in a background job runs in
  the instance the session has, or loads the session's instance; `get plugin` lists it and the
  trail records one `lifecycle.load` and one `lifecycle.unload` for it. Unloading, disabling,
  removing or reloading a package, and the session's end, now record the unload (#304, ADR-0995).
- **`kill %N` ends a job that is reading from a package**, and Ctrl-C ends a contributed command
  or a bounded contributed target read in the foreground: the invocation is cancelled through the
  supervisor, the line ends as interrupted (130), and the instance stays loaded for everyone else
  (ADR-0998). A shell leaving with such a job leaves as soon as the job has unwound.
- **A package is loaded once, however many evaluators reach it at the same moment.** A job and the
  foreground that both find a package unloaded take one turn per package id; the one that waited
  runs in the instance the other started (ADR-1026, case 174).
- **An invocation beyond a package's concurrency ceiling waits for a slot.** It is sent when an
  invocation of the instance ends — a job finishing, `kill %N`, the cancellation `take` sends
  upstream — and refused with `runtime.concurrency_limit` only when ten seconds pass, naming the
  invocations that hold the slots and what ends them. `get <target> | take 1 | each { … }`
  against a one-at-a-time package now runs (ADR-1027, case 175).
- **A package's qualified command backgrounded alone runs as a job.** `echo:emit --count 2 &` was
  taken for a program and refused; it now runs, and meets the confirmation gate a destructive
  command meets in the foreground (b3393a72).
- **`get plugin` measures.** `memory` is the instance's current allocation as the supervisor
  sampled it, `cpu_time` is new — `utime + stime` for a native process, null for a component,
  whose CPU time nothing measures — and `jobs` counts the invocations running in the instance
  (#222, ADR-0997, ADR-0998).

## The supervisor answers on one channel, and a view belongs to its invocation

- **An invocation's stream carries its whole answer.** A failed result ends the stream with its
  error; a cancellation the package made without being asked ends it with `stream.cancelled`; a
  clean `streams.close` holds the consumer's end open until the result arrives. A command that
  stopped short now fails after the values it sent, where it used to succeed with a truncated
  answer, and a refusal from an unbounded target is reported once (#154, ADR-0992, cases 146 and
  129).
- **A view closes with its own invocation and no other.** `views.open` names the invocation that
  owns the view, and two view-opening invocations of one instance each keep their view to their
  own end (#157, ADR-0991). A package built with an earlier SDK that opens a view while several
  invocations are open is refused, and the refusal names the way out: `ono-kuang-sdk` 0.6.5, or
  `runtime.max_concurrent_invocations: 1` in its manifest (ADR-1028).
- **A plugin child that dies before its first confinement control names why** — for example
  `Permission denied (os error 13)` for a working directory it could not enter — where the refusal
  said "an earlier mandatory control failed first" (#197, ADR-0990, case 145).
- **The supervisor's tier-and-limits record is `ExecutionEnvelope`**, named for what it is
  (#198, a pure refactor).

## Contributed places and relations reach as far as core ones

- **A pin on a contributed place survives its session.** `jump @<pin>` reads the place again from
  its kind's target in a new session; a pin whose kind no installed package contributes costs only
  itself — `find place` and every other pin keep working, `jump @<pin>` names the pin and its
  type, and `unpin <name>` removes it (#129, ADR-1005, case 165).
- **Spatial words load the lazy package that answers them.** `find place --role <role>`,
  `find place --type <kind>`, `jump <kind>/<key>` and `jump @<pin>` load the installed package
  whose on-disk declarations name that role or kind, and only that package: a typo starts nothing
  (ADR-1005, ADR-1021, case 171).
- **A relation has a name and a cost.** A manifest shape may read
  `<from>-><to>[; name=<word>][; cost=<class>]`. `follow` takes the name and `look` and `near`
  print it; the id still works. A relation declared beyond `normal` is shown as
  `available on request` by a default `look`, and the package is asked only for the relations the
  caller wants (#224, ADR-1006, ADR-1020, case 166).
- **A relation may name another package's kind of place.** It waits until a package contributes
  that kind, in either load order, and `follow` refuses with `spatial.unsupported` naming the
  schema it waits for. With the second package installed and not yet loaded, `follow <name>`
  loads it and arrives at the place it answers for (#224, ADR-1008, c8c51268, case 168).
  Unloading a package withdraws its relations, and a reload declares them anew (0bdf84a5,
  case 170).
- **A contributed place sits in the scope its package declares.** A schema may state
  `scope: [<field>, …]`, outermost first, and its places sit in nested `plugin` scopes inside the
  host — `plugin:cluster=kind-ono/namespace=shop` — with `scope_crossing` in the trail and the
  identity unchanged. A package declares scopes for its own schemas only, read from the directory
  the session loaded it from (#224, ADR-1009, ADR-1030, case 169).
- **A search that reads a contributed target to its bound says so.** `find place` states on the
  diagnostic stream that it read a target as far as its 1024-object bound, with the total the
  package stated or that it stated none (#224, ADR-1007, case 167).
- **A bounded contributed answer streams.** `get <contributed target> | take N` finishes on the
  Nth value and stops the package, and a failure after some values fails the command beside them
  (#224, ADR-1011, case 172).
- **`watch <contributed target>` says why it cannot.** It answers `provider.unsupported` — a
  contributed target declares no event vocabulary — before any package starts, where it ran the
  `watch` program on `PATH` (#224, ADR-1013, case 173).
- **A contributed object can be acted on through the action its package declared**, at the
  provider registry: the command whose verb is the operation and whose `action` accepts the
  object's schema, held to its declared risk, confirmation, defaults and dry run (#224,
  ADR-1012, ADR-1024). No command a user types reaches this path yet; `docs/STATE.md` records
  that as a finding outside the issue.

## Host services that answer

- **`relations.contribute` keeps a package's edges for the session**, in the registry `look`,
  `follow` and `map` already read, along the package's own declared relations only, attributed to
  the package and never `exact`, at most 1024 edges per package and at most 4096 bytes per edge
  as sent, withdrawn on unload; `relations.query` reads them as `inferred` (#203, ADR-1014,
  ADR-1031, case 176).
- **`history.append` records an entry the host attributes.** A package's entries live in
  `<state>/ono/history-packages/<package-id>.jsonl`, apart from the operator's history, never
  recalled at the prompt, redacted before the write, and bounded to the newest 1000 per package;
  `history.query` reads both, each entry naming its `package` (#203, ADR-1015, case 177).
- **`secrets.request` says why this shell keeps no secret store.** It stays `provider.unavailable`
  and issues no handle: "this shell keeps no secret store: the operator has nowhere to put a
  secret, the environment is not one, and no host call this build serves would consume a handle,
  so none is issued (ADR-1016)". A name outside the grant is `capability.scope_violation`, audited,
  and the shell's environment is never read for a secret (#203, ADR-1016, case 178).
- **An operator catalog names the authorities its artifact servers are verified against.**
  `catalog.certificate_authorities` lists PEM files; that catalog's HTTPS artifacts are verified
  against exactly those, in place of the public roots. Only an operator catalog may name them, an
  unreadable file refuses the fetch without falling back, and the digest and signature checks are
  unchanged (#153, ADR-1010).
- **The KUANG/11 contracts say they are implemented.** `errors.v1.yaml` and six contracts beside
  it opened with "Nothing here is implemented" (#184, a4214f84, ee4c6468).

## Three independent reviews, and what they changed

After the workstreams were merged, two reviews that had not written the code read the diff
`1913ad94..a69f0223` — one over regressions, contracts and architecture, one over security. Every
finding they marked major is fixed with a test that failed first:

- **Sharing the instance had two regressions.** A job and the shell that both loaded a package
  lazily raced, and one side's instance was shut down under its invocation (ADR-1026); and a job
  holding the only slot of a package with the SDK's default ceiling made the shell's next `get` of
  it fail, as did a streamed bounded answer whose later stage used the same package (ADR-1027).
  Several open invocations also became common, so a package built with an earlier SDK that opens
  a view now meets ADR-0991's refusal often enough for the refusal to name the way out
  (ADR-1028).
- **A package that authors both of its declarations could escape the confirmation**, by
  declaring a command `read` on disk and `destructive` in its hello (ADR-1022).
- **A job could read the keystrokes typed for the shell as an answer** to a permission question,
  an `always` among them, because the instance kept the consent source of whoever loaded it
  (ADR-1023).

They also found, and the same round fixed: a contributed action at the provider registry that
ignored its command's risk and declared defaults (ADR-1024); `--confirm` written before a selector
taking the selector as its value (19670ee0); an expensive relation computed whenever a cheap one
from the same kind was wanted (ADR-1020); an unloaded package's relations still answering
(0bdf84a5); a kind-word typo starting packages (ADR-1021); one package declaring the scopes of
another's schema, read from a different plugin path than the session's (e1a6437c, recorded as
ADR-1030); a backgrounded qualified command taken for a program (b3393a72); and a refusal naming
`ono.plugin/1` records (481d1380). Before the reviews, the orchestrator's own checks had found two
more: a hello that understated its risk escaping the confirmation (ADR-1002), and a job reading
from the shared instance that `kill %N` could not end (ADR-0998).

A third independent review read the fixes themselves, `ee4c6468..6e329d0f`, and found one major
defect, fixed test-first before the release:

- **A package's pushed edges were bounded in count only.** An edge's metadata could fill a 1 MiB
  frame, and 300 such edges grew the shell to 1.7 GB of resident memory, far past the package's
  own 64 MiB budget. An edge now takes at most 4096 bytes as sent; a call carrying a larger one is
  `resource.item_limit` and nothing of it is kept (b6070bc8, ADR-1031).

It also found that an invocation waiting for a slot lost the consent source ADR-1023 gives it, so
its question went unasked at a terminal (f426679e), and that a job test had stopped proving its
report comes at a prompt (c1b31897); both are fixed. The cost of resolving every pushed edge on
each spatial read is recorded in `docs/STATE.md`.

## Performance

Measured on 2026-11-11 against the published v0.6.4 package, with release builds, the same
example plugin binary for both, on a host at load 1.4; two rounds each, so a cell holds the range:

| | v0.6.4 | v0.6.5 |
|---|---|---|
| `ono -c true`, p50 | 6–7 ms | 7 ms |
| load a package and one invocation, p50 / p95 (n = 20) | 21–22 / 22–26 ms | 21–22 / 22–23 ms |
| 200 invocations in one shell, p50 (n = 5) | 260–262 ms | 230–231 ms |
| the shell's peak resident memory over those 200 | 22.8 MB | 24.4–24.8 MB |

Nothing measured got slower. Two hundred invocations in one shell take 12 % less time, and the
shell holds about 2 MB more at its peak.

## Deferred and not met

Nothing the milestone asked for. Its inventory is unchanged — the 13 issues are in the table
below — and each is met. What an issue settled by decision is recorded in an ADR:

- **#224 (6) — `subscribe` for a contributed target is rejected.** `PluginProvider::act` carries
  out a contributed action (ADR-1012, ADR-1024); the other half of the part, subscribing to a
  contributed target, was declined by ADR-0588 and is made explicit by ADR-1013: `watch` refuses
  with its reason until an event vocabulary for contributed targets is decided.
- **#156 — met in the form ADR-1001 chose.** The issue asked that a destructive contribution
  prompt at a terminal. The core gate it is routed through does not prompt, so a contribution
  refuses at a terminal and names `--confirm` exactly as `protect` does.
- **#203 — `secrets.request` is declined by ADR-1016.** A store needs an operator-controlled
  source, a handle and a host call that consumes the handle; only the handle exists. That is new
  product surface for a milestone that plans it.
- **#222 — a component's `cpu_time` is null.** wasmtime keeps no per-instance CPU account, and
  unknown is null, never zero (ADR-0997).
- **Two restrictions fail closed until a host call names its invocation.** A `recovery.restore`
  is refused while another invocation of the instance that did not declare it is open
  (ADR-1022), and a foreground permission question that arises while a job's invocation is open
  in the same instance is answered `permission.required` (ADR-1023). Giving host calls an
  `invocation`, as `views.open` has, would lift both; it is a protocol change.

What the run found outside the milestone's issues — among them that no command a user types
routes a contributed object to `ProviderRegistry::act`, the cost of resolving pushed edges, and
the Kubernetes provider's own examples and live tests, which invoke `remove k8s-resource` without
`--confirm` — is in `docs/STATE.md` → *Found, not yet filed*.

## Compatibility

Nothing a correct v0.6.4 configuration relies on was removed, and components compiled by v0.6.4
load unchanged. One field of one record is gone, and a package is now held to declarations it
could leave out before. `docs/MIGRATION.md` §15 lists what can look different: `get plugin` answers
`ono.plugin/2` without `isolation`, with measured `memory`, a new `cpu_time` and a live `jobs`; a
destructive contribution needs `--confirm`, the Kubernetes provider's `remove k8s-resource`
included; a mutating contribution needs a declared risk no lower than its capabilities; a
destructive host call needs the command that declared it; a job shares the session's instances,
and its audit trail shows one load and one unload; an invocation beyond a package's ceiling waits
for a slot; a view opened without its invocation by an older SDK is refused while several are
open; a command that stops short fails with `stream.cancelled`; a bounded contributed answer
streams; `watch` of a contributed target refuses; a manifest shape with `; name=` or `; cost=`
needs this release, and an older host refuses the package; a schema may declare `scope`;
`relations.contribute` and `history.append` answer, a pushed edge larger than 4096 bytes is
refused, and `secrets.request` states its reason; and an operator catalog may name
`certificate_authorities`. The wire protocol stays `kuang-host/11.1`: every addition to it is
optional.

## Install

The `.deb` and `.rpm` for both architectures are on the release page:

```bash
sudo apt install ./ono_0.6.5_amd64.deb          # or ono_0.6.5_arm64.deb
sudo dnf install ./ono-0.6.5-1.x86_64.rpm       # or ono-0.6.5-1.aarch64.rpm

chsh -s /usr/bin/ono                             # make it your login shell
```

Verify before you install, in this order — the signature over the manifest first, the artifacts
against the manifest second. The sequence is the one in `docs/reference/release-verification.md`
and the README, and `scripts/verify-release.sh --dir <dir>` runs it on a download directory:

```bash
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github\.com/godspeed-you/ono-sendai/\.github/workflows/release\.yml@refs/tags/v' \
  SHA256SUMS
sha256sum --check --strict --ignore-missing SHA256SUMS
```
