# Ono-Sendai v0.3.0 — the tools you already have, typed

Two things at once: the **External Command Adaptation Layer** of the v0.3 enhancement
specification, and the completion of the v0.2 command surface — every one of the 170 commands the
registry declares now runs.

`ps aux` still prints what `ps aux` prints. But `ps aux | where cpu > 20` works too, because the
shell recognised the invocation, ran the real `ps` with an explicit field list and turned its
output into `ono.process/1` records. No screen scraping of human output, no reimplementation of
your tools: the tool runs, and its own machine-readable format is decoded. Where that is not
possible, the command runs raw, exactly as typed.

> Bash is a command interpreter. PowerShell is an object shell. Ono-Sendai is a systems interface.

## The adaptation layer

- **22 adapters, 9 first-party packs, 14 tools** — `ps`, `ip`, `ss`, `lsof`, `stat`, `df`, `find`,
  `git`, `journalctl`, `systemctl`, `lsblk`, `findmnt`, `lsns` and `curl`. Each declares the exact
  invocations it claims, the version range it was proven against, and the canonical `ono.*/1`
  schema it answers with — `ip a` becomes `ono.interface-address/1`, `journalctl -u nginx` becomes
  a stream of `ono.journal-event/1`.
- **Invisible on success, inspectable on demand.** An adapted command renders exactly like a
  native result. `explain <command>` says which adapter was selected and why, `type` and `inspect`
  show the plan, and every adapted value carries its provenance — which pack, which version, which
  invocation it came from.
- **The raw path is guaranteed.** `raw <program> …` bypasses the layer unconditionally. A tool
  that is not listed runs raw; a listed tool runs raw whenever the typed invocation is not one its
  adapter declares, or the installed version is outside the declared range. Adaptation is never
  something that happens to you behind your back.
- **Text tools stay text tools.** No first-party adapter claims `cat`, `grep`, `sed` or `awk`.
  `ps aux | grep foo`, `ip a | head` and `find . | wc -l` behave exactly as they always did.
- **Executable identity is pinned**, version probes are declared, bounded and cached, and decoders
  stream — a decoder that cannot parse a row cannot take the shell down with it.
- **Adapters are extensible and remote-aware.** A third-party KUANG/11 package can ship a
  declarative adapter with no code, under the same capability broker (`process.exec` scoped to
  named executables), and inside a link frame an adapted command is negotiated on the far side.
- **The claims are published, not asserted.** `docs/reference/adapters/` carries the generated
  compatibility matrix with tier, version range, invocations, schema and documented limitations
  per adapter; the acceptance image installs the real tools and runs live conformance against
  them; the overhead of the adapted path over the raw one is measured.

## The command surface, completed

Every declared verb now reaches every target it was declared for — 170 commands, generated help,
completion and `explain` for all of them:

- **Files** — `read`, `write`, `tail --follow`, `find file`, `copy`, `move`, `remove`, `open`,
  `watch file`, `trace file --users`.
- **Storage** — `get device` from `/dev` and sysfs, `get filesystem --mounted` from udev's probe,
  `mount`/`unmount` through `mount(2)` and `umount2(2)`, mount write paths, `watch`/`trace mount`.
- **Network** — route, interface and socket write paths over netlink, `resolve dns` through the
  system resolver, `test port` with timing, `watch`/`trace` for interfaces and routes.
- **Services and logs** — `get log` as `ono.log-record/1` with severity named, `get journal` and
  `tail journal` as `ono.journal-event/1`, `set service --enabled`.
- **Identity** — users, groups and membership through the account tools, `get session` from
  systemd-logind over D-Bus, `watch`/`trace` for both.
- **Containers** — `get container`/`get image` through the engine API, start, stop, restart,
  remove, set, and `enter`, `watch` and `trace` a container.
- **Remote** — link definitions and host records in the shell's own host file, `connect host` as a
  one-shot link, `test host` reporting the handshake, `watch link`, `trace host`.
- **Packages and plugins** — `get package`/`find package` from dpkg's machine formats, `install`,
  `remove` and `set` through apt; the KUANG/11 lifecycle end to end: `install`, `verify`,
  `inspect`, `load`, `unload`, `set plugin`, and `get`/`grant`/`revoke capability` with the audit
  trail.
- **Data and language** — `join --on`, `diff --identity`, `tail N [--follow]`, `sort` without a
  key, string `+`, `each { … }` with `@` bound, `alias`, user functions, `now()` and RFC 3339
  literals, `NAME=value command` scoped to one pipeline, `kill %N` from the job table.
- **Configuration** — typed, layered and live, with provenance: `get config` says where every
  value came from, `set config` writes it back.

## Installable packages

The first release you can install rather than copy: `.deb` and `.rpm` for x86_64 and aarch64,
built by `scripts/package.sh` and installed into fresh Debian and Fedora containers — as root and
as an unprivileged user whose login shell is `ono` — by `scripts/package-check.sh` before
publication. They register `/usr/bin/ono` in `/etc/shells` and ship the licence and the generated
command reference under `/usr/share/doc/ono/`.

## Behaviour that changed since v0.2.0

- A failed `ActionResult` row exits 1, so a mutation that did not happen cannot look like success.
- The error value in `to json` follows `ono.error/1`, and `operation` carries the command id.
- `let` and `( … )` capture a pipeline's **value** rather than its exit status.
- `set`/`remove` of system targets dispatch through the registry, so any mutating verb a provider
  advertises the capability for is bindable.
- Configuration is typed and layered, and `render.table.max_rows` truncates rendered tables
  visibly rather than silently.

## Install

```bash
sudo apt install ./ono_0.3.0_amd64.deb          # or ono_0.3.0_arm64.deb
sudo dnf install ./ono-0.3.0-1.x86_64.rpm       # or ono-0.3.0-1.aarch64.rpm

chsh -s /usr/bin/ono                             # make it your login shell
```

Or build it: `cargo build --release -p ono-cli`. See the README for configuration, the plugin
layout and login-shell setup.
