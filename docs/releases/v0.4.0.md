# Ono-Sendai v0.4.0 — the machine is a place

The v0.4 enhancement specification, the **Spatial Systems Interface**, implemented on top of the
v0.2 base and the v0.3 External Command Adaptation Layer. The shell you could already pipe typed
objects through is now one you can *stand somewhere in*: the machine has a geography, you move
through it, and every place says who observed it, how fresh that is and what it was not allowed
to see.

> Bash is a command interpreter. PowerShell is an object shell. Ono-Sendai is a systems interface.

## The spatial interface

- **Discovery before naming.** You find the listening web service without knowing that it is
  nginx, or which pid it has: `look` describes where you are, `near` lists what is next to you,
  `find place --where local.port == 8080` searches. The two acceptance scenarios that prove this
  have a house rule — no case may type the name of the object it discovers.
- **Fourteen spatial commands, one contract each** — `look`, `near`, `enter`, `follow`, `jump`,
  `back`, `up`, `home`, `trail`, `find place`, `map`, `map links`, `pin` and `unpin`.
  `help spatial` is the overview, each has a generated reference page, and the pages are held
  against the machine-readable registries on every gate run.
- **Hierarchy and graph stay separate.** `up` walks the canonical hierarchy, `back` walks your
  trail, `follow` traverses a relationship edge and refuses a canonical child that is not one. An
  object keeps *every* relationship parent while naming one canonical parent, so "where does this
  belong" and "what is it connected to" never get confused.
- **Identity survives pid reuse.** A process is identified by a lifetime descriptor, not by its
  pid. A process you visited and that then exits becomes a **tombstone** — visibly distinct from
  a place that never existed, refusing traversal, never resolving to a live object, and still
  reachable through `back` with its trail record intact. The replacement process that inherits
  the pid is a different place.
- **Permissions are honest.** Every neighbourhood group carries one of six defined states.
  Denied is reported as denied, never as an empty collection; an unavailable group is distinct
  from an empty one; a reference field a provider left null is not an exit with zero things
  behind it. Navigation never escalates privileges.
- **The map, at four levels of terminal.** `map` renders as text into a pipe and collapses
  layout — not semantics — on a narrow terminal; `map --json` answers a bounded graph document
  with no terminal at all; at a real PTY the full-screen view opens, and `map --live` shows an
  edge appear when a connection opens and vanish when it closes. Moving focus never moves the
  shell: only Enter does.
- **Storage integrates with cwd.** Entering a directory moves place and cwd together; entering a
  process or a socket moves neither; `PWD` never carries a non-directory place; a mount boundary
  says what it is mounted from.
- **Remote hosts are places.** A linked host has a root distinct from the local one, `jump`
  announces the boundary in plain text, the trail records the crossing, and a hostname that is
  not a link is refused rather than resolved.
- **It is all still the object pipeline.** `look --json` and `near` read straight back into v0.2
  commands, a pipeline result can be entered as a place, and a `find place` result composes with
  `where`, `take` and `count`.
- **KUANG/11 packages can extend the geography.** A package's edges stay out of the map until its
  capability is granted, and carry the contributing package as their origin once they appear.

## Also since v0.3.0

- **KUANG/11 isolation and signatures.** A `native-process` instance is confined between fork and
  exec — `RLIMIT_DATA` at the negotiated `memory_max`, the `cpu_budget` as a nice level, bounded
  descriptors and file size, no core dumps, its own session, `NO_NEW_PRIVS`, a private working
  directory and an environment built from nothing but `PATH`, `HOME`, `LC_ALL` and `TZ`. The host
  measures what it limits, so `memory_current`, `memory_limit` and `cpu_time` are figures rather
  than nulls. Package signatures say which key signed which files, `verify plugin` answers about
  signature *and* publisher trust and can refuse on either, and a declared contribution is a
  registry entry before it ever runs.
- **Remote links that certify their peer.** A transport that verifies the far side, host-key
  pinning that refuses an unknown key and answers `Ono-Sendai-E0603` for a changed one, and an
  agentless fallback: a link to a host with no `ono` agent falls back to a reduced provider set
  that really reads that machine, instead of pretending to be complete.
- **Fuzzing in the gate.** The five targets of spec §35.6 — parser, serializers, remote protocol,
  plugin protocol, system decoders — with a corpus and a bounded run on every gate.
- **Shell polish.** Themes as a setting or a file; completion answered from the providers without
  ever blocking the prompt; a prompt that carries the branch; `to bytes --field` writing one field
  verbatim; JSON written in schema order; a `watch` the kernel tells where the kernel can tell it;
  a unit's dependencies; a CPU share that names the window it is a share over; a result too large
  to retain that says so instead of lying.

## Known, measured, not hidden

**`get socket | take 1` pays for the whole table on a host with thousands of sockets.** Acceptance
case `152` opens 5 000 listening unix sockets and measures: the first socket row costs 61 ms and
the first connection row 61 ms against §34's 50 ms budget, while the *whole* table costs 68 ms.
The shape is the diagnosis — the provider reads the complete `sock_diag` dump before it yields
row one, where §34's per-row budget assumes it streams. On an ordinary host (2 sockets) the same
measurement is 47 ms and within budget, and every other §34 budget in that case — cold start under
load, the whole socket table — holds.

The case stays red rather than relaxed, which is why this release ships with one failing
acceptance case and says so here. It is a performance defect, not a correctness one: the rows are
right, they arrive later than the specification allows. The fix is to make the socket provider
stream, and it is the next thing on the board.

## Notes for upgrading

- `look` shadows util-linux `look(1)`. The bare name belongs to the spatial command; the program
  stays reachable as `exec:look` (ADR-0124).
- `find` is unchanged and still findutils — the spatial search is `find place`, beside
  `find file` (ADR-0124).
- Spatial refusals are their own error family, `Ono-Sendai-E1001`–`E1014` (ADR-0125), and every
  one of them is a structured value a script can read.

## Install

`.deb` and `.rpm` for x86_64 and aarch64 are attached below. Each is installed into fresh Debian
and Fedora containers on both architectures before it is published — as root and as an
unprivileged user whose login shell is `ono`:

```bash
sudo apt install ./ono_0.4.0_amd64.deb          # or ono_0.4.0_arm64.deb
sudo dnf install ./ono-0.4.0-1.x86_64.rpm       # or ono-0.4.0-1.aarch64.rpm

chsh -s /usr/bin/ono                             # make it your login shell
```

Or build it: `cargo build --release -p ono-cli`. See the README for configuration, the plugin
layout and login-shell setup.
