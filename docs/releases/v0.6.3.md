# Ono-Sendai v0.6.3 — language and contract stabilization

A stabilization release on top of v0.6.2. It changes what the shell's language and contracts
promise and makes the repository check those promises: one implementation of the operators, typed
arguments that refuse instead of silently dropping, refusals that say what decided them, functions
that are pipeline stages wherever they stand, blocks that stream inside functions and run as
background jobs, a `measure` that holds nothing, a streaming serializer, an `explain` whose plan is
data, completion outside a terminal, and command examples that are run against the schemas their
commands declare. The GitHub milestone `v0.6.3` ("Language and Contract Stabilization") is the
release inventory; it has no narrative specification, and ADR-0929 records that each of its issues
is a requirement whose exit test decides it.

> Stabilize Ono's command semantics and language behaviour before changing higher-level system
> abstractions.

Every issue was reproduced against the starting tree (`c6554961`) before anything changed; none
turned out to be already satisfied. #191 in particular — a function between two stages — had been
described elsewhere as working, and was not.

## One language, held to its contracts

- **One operator semantics.** The pipeline's `where` and the session's `let`/`if` evaluated the
  binary operators in two copies that only happened to agree. One `evaluate_binary` serves both
  now, and a test pins 64 expressions and 9 conditions to the same answers in both places (#137;
  a pure refactor, so no test changed).
- **An argument is held to its declared type.** `get command --verb ["get"]` used to answer the
  whole registry because the list did not fit the `string` option and the filter was skipped. An
  evaluated selector or option now stands only where it fits its declaration — through the same
  coercion a word gets — and is otherwise refused with `type.mismatch` naming the parameter, the
  declared type and the received one. `let who = "root"; get user $who` now asks for the user
  named root (#168, ADR-0937).
- **A refusal says what decided it.** The fields a refusal carries — `stage`, `limit`, `consumed`,
  `setting`, `denied_because`, `control`, `execution_tier` — were in the error value and on no
  screen. The reporter now prints the fields `docs/contracts/hardening/refusals.yaml` declares as
  explaining each error, at a terminal and redirected alike (#180, ADR-0938).
- **No crash because nobody read the diagnostics.** A refusal written to a closed stderr turned
  exit 1 or 2 into a panic's 101. Every product diagnostic goes through a write that cannot panic,
  and `clippy.toml` refuses a new `eprintln!` (#163, ADR-0936).
- **A budget of zero admits nothing.** `limits.materialize_items = 0` (or `…_bytes = 0`) makes a
  stage that must hold its input refuse with `resource.materialization_limit` (E1103) before it
  reads anything — the error v0.4.1 §21.4 requires and nothing raised until now (#183, ADR-0934).

## Functions, blocks and jobs that stream

- **A function is a stage wherever it stands.** `get process | mine | take 1` used to run `mine`
  as a program. A call after another stage now feeds the stream into its body's first stage,
  without collecting it; a body that cannot read a stream is refused by name before anything runs,
  and `explain` names the call as a user function and says whether it streams (#191, ADR-0951).
- **A function body that runs `each { … }` streams** like one that filters, because a block request
  now names its site rather than a position in one stage list (#192, ADR-0950).
- **`each { … } &` is a job.** A backgrounded line containing a block, a function call or a
  program runs with an evaluator of its own: listed by `jobs` and `get job`, collected by `fg`
  with its status, stopped by `kill %N` with its children reaped; it never reads the terminal, and
  what it rebinds stays in it (#193, ADR-0952).
- **`measure` holds nothing unless asked.** Count, sum, mean, min, max and stddev are constant
  state; `--median` and `--percentiles` hold the distribution. A plain `measure` therefore works
  past the materialization budget and on an unbounded stream, where it answers after every value
  (#174, ADR-0953).
- **`to jsonl`.** One compact JSON document per value, written and flushed as each value arrives —
  to the terminal, a file or the next program — on bounded and unbounded streams alike, stopping
  cleanly when the reader leaves. `to json` keeps its one-document contract (#214, ADR-0954).

## Explain, completion and the terminal

- **`explain` is data.** `explain "get process | sort pid" | to json` — a quoted, braced or
  `$variable` subject — makes `explain` an ordinary producer of one `ono.execution-plan/1`, which
  later stages read; bare words keep spec §11.3's whole-line meaning. One session-aware builder
  produces the record, and the text at the prompt is drawn from it (#173, ADR-0942).
- **`explain` runs nothing.** A prefix assignment is understood exactly as execution strips it and
  its environment is shown (`explain NAME=value cmd`), but a value that could run code is shown as
  its source rather than evaluated, and a subject is never re-parsed from expanded text
  (#223, ADR-0943 as amended by ADR-0939).
- **Global work is visible.** Commands that acquire the whole system graph declare it in their
  contract — `acquisition: {scope, cost}` — and `explain` shows `acquisition  global, moderate`;
  spec-check refuses a contract that understates it (#177, ADR-0947).
- **Completion without a terminal.** `ono --complete '<line>' [--cursor N]` answers what Tab would
  offer as one `ono.completion/1` document, through the same completer as the prompt (#176,
  ADR-0945); case 060 now measures the first completion end to end in the container.
- **Completion says when it was cut short.** A set truncated at the soft budget or the candidate
  ceilings is marked incomplete, and the listing ends with `…` (#178, ADR-0944).
- **Functions and aliases complete**, live, with their signature or expansion beside them
  (#223, ADR-0946).
- **`get process --tree` draws a tree at a terminal** and stays the table of roots — and the same
  records with `children` — anywhere else (#223, ADR-0948).

## Contracts the repository checks

- **Command examples are run against the declared schema.** `cargo xtask conformance` now also
  generates `command_conformance.rs`: every command example that can run hermetically is run
  through the binary and each value is validated against the command's declared output; an example
  that produces nothing must say so (#149, ADR-0935, ADR-0941). It found and fixed eight real
  mismatches — `inspect limits`, `get context`, `type`, `inspect`, `trace route 0.0.0.0/0`, and four
  examples that could not run as written — and one more in this release's own `to jsonl`.
- **Every schema document is embedded**, from a list generated from the directory (#159, ADR-0930).
- **Every machine-readable contract is indexed**, `docs/baselines/` included (#171, ADR-0931).
- **`SECURITY.md`'s boundary table is generated** from `security_boundaries.yaml`, and spec-check
  fails when they disagree (#170, ADR-0932).
- **One key names the history ceiling.** `history.result_cache` is a retired name for
  `limits.history_bytes_total` (#175, ADR-0933).

## The referee, repaired first

On the machine this release was qualified on, the gate was red before any change: the journal and
log tests read the host's real journal (4 GB there) and ran into their watchdog. They now read a
fixed `journalctl` at the external boundary, and each asserts the exact records kept (#280,
moved into this milestone by ADR-0929).

## An independent review, and what it changed

After the work packages were integrated, two independent reviews that had not written the code —
one adversarial over correctness, streaming and cancellation, one over release readiness and
security — read the whole diff. They found four release-blocking defects, each now fixed with a test
that failed first:

- **`explain` could run code.** A prefix-assignment value written `X="$( … )"` was evaluated, and a
  bare or `$variable` subject was expanded and parsed again, so a crafted filename matched by a glob
  ran a command. `explain` now evaluates only what can do nothing but read the session, shows every
  other value as written, and never parses expanded text again (ADR-0939;
  `explain_runs_nothing.rs`, case 387).
- **A background job could move the shell's working directory**, because the process has one. A
  job now refuses `cd` and the context moves that change directory (ADR-0955; case 391).
- **A function ending in `each { … }` piped into a mutation deadlocked**, a regression of #191/#192:
  the block's requests were answered only after the next stage had started, and a mutation reads its
  whole input while starting. They are answered while it starts now (`streaming.rs`).
- **Ctrl-Z on a program fed by `to jsonl` left the shell without a prompt.** The stop is noticed and
  the program filed as a stopped job (ADR-0956).

They also found, and the same round fixed: a job's environment reaching the shell's `get env`, a
process group signalled after it was reaped, a job dropped from `jobs` while its child still ran, a
FIFO reader leaving that ended the interactive shell, per-item failures of an endless `to jsonl`
held until it ended, a fed program's end of input arriving up to 100 ms late, a completion panic on a
non-breaking space, `--complete`/`--help`/`--version` exiting 101 on a closed standard output, the
tree view's unbounded guides, and a conformance harness that passed examples producing nothing
(ADR-0940, ADR-0941). Two findings were refuted with evidence, and what is outside the milestone is
recorded in `docs/STATE.md`.

Integration found three more, each fixed with its test: `measure` refused by a zero budget although
it holds nothing (49ec3b34), `to jsonl`'s line stream undeclared in `to`'s contract (22863575), and
the first correction of that making every `stream<string>` producer end the object stream
(65ed3e66).

## Compatibility

Nothing a correct v0.6.2 configuration or script relies on was removed, and `history.result_cache`
keeps working as a retired name. Some answers are stricter or richer, and `docs/MIGRATION.md`
§11–§13 lists each: a plain `measure` reports its median only with `--median`; a wrongly typed
evaluated option is refused instead of ignored; refusals print their deciding fields before the help
line; a zero budget is E1103; `type`, `inspect`, `inspect limits` and `get context` answer typed
records; `explain` with a delimited subject is a producer and never runs its subject; a background
job may not change directory; and a redirected stream whose reader leaves ends that line with 141.

Two exit tests are met in the form the release chose, which ADR-0942 and ADR-0954 record: #173's
`explain <pipeline> | to json` composes when the subject is delimited (`explain "…" | to json`),
because spec §11.3 gives the unquoted words the whole line; and #214's streaming serializer is
`to jsonl`, proven on an unbounded `tail file --follow` source, because `to json`'s one-document
contract stays and `map --live` needs a terminal or a declared consumer that the hermetic tests
cannot provide.

## Install

The `.deb` and `.rpm` for both architectures are on the release page:

```bash
sudo apt install ./ono_0.6.3_amd64.deb          # or ono_0.6.3_arm64.deb
sudo dnf install ./ono-0.6.3-1.x86_64.rpm       # or ono-0.6.3-1.aarch64.rpm

chsh -s /usr/bin/ono                             # make it your login shell
```

Verify before you install, in this order — the signature over the manifest first, the artifacts
against the manifest second. The sequence is the one in `docs/reference/release-verification.md`
and the README, and `scripts/verify-release.sh --dir <dir>` runs it on a download directory:

```bash
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github\.com/godspeed-you/ono-sendai/\.github/workflows/release\.yml@refs/tags/v' \
  SHA256SUMS
sha256sum --check --strict --ignore-missing SHA256SUMS
```
