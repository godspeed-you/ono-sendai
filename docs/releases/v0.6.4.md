# Ono-Sendai v0.6.4 — system and spatial model stabilization

A stabilization release on top of v0.6.3. It fills the places where the system model and the
spatial interface named something no provider answered, and it makes the answers cheaper: cgroups,
namespaces and addresses are provider targets, a process reaches the endpoints it is connected to,
a container and a namespace boundary are marked where a place lies behind one, the map searches
beyond what it drew, a selective `where` hands the provider the comparisons it declared, and a
`trace` or a keyed selector asks for the one object it names. The GitHub milestone `v0.6.4`
("System and Spatial Model Stabilization") is the release inventory — 25 issues, as ADR-0862 and
ADR-0929 established for the two releases before it — together with what `implementation` carried
past v0.6.3: the maintenance prelude #301–#303 and three rounds of dependency advisories.

> Stabilize the system providers, adapters and process execution, and the spatial navigation and
> map built on them, before the KUANG/11 ecosystem and the remote and change tranches.

Every issue of the milestone is settled. Twenty-four are closed — twenty-one by what they asked
for, and #209, #213 and #221 with their remainders split out or, for one part of #221, rejected by
an ADR. One requirement is **not met**: #187's 250 ms target for a selector miss at Profile M.
A miss costs 42 % less than in the v0.6.2 baseline, and #187 stays open, outside the
milestone, as the record of the debt (*Deferred and not met*, below).

## Security, and one step after upgrading: recompile compiled KUANG/11 components

> **After installing v0.6.4, every compiled KUANG/11 component needs `kuang-compile` once.**
> Loading one that was compiled by v0.6.3 is refused with `Ono-Sendai-K11105
> load.component_not_compiled`, reason `incompatible`, and the message names the exact command —
> for example `kuang-compile ~/.config/ono/plugins/dev.example.echo/runtime/echo.wasm`, with
> `--store <store>` where the store it looked in first is not the one `kuang-compile` picks by
> itself. Running that command is the whole recovery; reinstalling the plugin with
> `install plugin` does the same. Native-process packages are not affected.
> `docs/MIGRATION.md` §10 explains the compiled store and §14 this release.

v0.6.3 ships wasmtime 48.0.5 and rustls 0.23.45. This release moves wasmtime to 48.0.8, rustls to
0.23.46, tokio to 1.54.1, rustls-webpki to 0.103.16, webpki-roots to 1.0.11 and rusqlite to 0.41.1
for the advisories published since the v0.6.3 tag (RUSTSEC-2026-0346 … -0349, -0352 … -0359,
-0361 … -0364, -0378, -0379, -0381, -0382, -0386, -0420, -0422 … -0424, -0459). A compiled KUANG/11
artifact is keyed on the exact wasmtime release (ADR-0916), so each compiled component is refused
once with `Ono-Sendai-K11105`, naming the `kuang-compile` command to run. Native-process packages
are unaffected.

## The system model answers what it names

- **Cgroups, namespaces and addresses are provider targets.** `get cgroup`, `get namespace` and
  `get address` answer from the kernel, and the spatial exits that named them — a process's
  cgroup and namespaces, an interface's addresses and routes — lead somewhere (#206, ADR-0971).
- **A process reaches the endpoints of its connections.** `process.connects_to` is composed from
  the sockets a process holds, so `follow endpoints` from a process arrives at the remote ends
  (#206, ADR-0972).
- **A file's owner is read when it is asked for.** The account lookup happens on `follow owner`
  or `--resolve`, and a look that never asks pays nothing for it (#206, #216, ADR-0973).
- **`get kernel`.** A new provider serves `ono.kernel/1` — release, version, architecture,
  hostname, OS, boot id, boot time, uptime, total memory — and the root place fills `kernel` and
  `uptime` from it (#207, ADR-0964).
- **One filesystem per superblock.** Two anonymous mounts that share source and type are two
  filesystems when the kernel says so, and `get filesystem` counts what the mount table counts
  (#167).
- **A process keeps one identity across a clock step.** `start_ticks`, the kernel's own start
  time, joins `ono.process/1`, and the spatial identity is keyed on it (#152, ADR-0969).
- **`trace container` reaches the container's processes, cgroup, namespaces and mounts.** The
  processes are the ones in its cgroup; `ono.container/1` gains `mounts` from the engine
  (#221, ADR-0968, ADR-0974).
- **A busy file is `io.busy`.** Running a script a writer still holds answers
  `Ono-Sendai-E0305 io.busy` and names the file, with status 126 as before (#186, ADR-0962).
- **An adapter may hold back the stderr lines it declares.** `ss`'s `RTNETLINK answers:` lines no
  longer reach the terminal on success; on failure everything is passed through (#138, ADR-0966).
- **A streamed adapter child's status stands under load.** The reader records why the stream
  ended before the consumer can see it close (#158).

## Orientation in the spatial interface

- **Boundaries are marked.** An observed process belongs to `container:<id>` and, where its pid
  namespace differs from the shell's, to `namespace:pid:[<inode>]`. The concise path shows the
  markers, the trail keeps them, and stepping across one prints `crossing scope: A -> B` on the
  diagnostic stream (#211, ADR-0983).
- **The map searches beyond what it drew.** `/` in the map finds places the frame left out and
  says where they are; a collection is discovered behind the prompt, so completion offers places
  the last view did not hold (#212, ADR-0984).
- **`map --cluster user|service|container`** groups what was not drawn by the dimension asked
  for, and the map of a directory draws its entries and clusters the rest by kind (#209, #216,
  ADR-0976, ADR-0981).
- **A directory points out what changed recently**, from the latest of an entry's times
  (#216, ADR-0975).
- **High memory and restart loops have evidence.** `high_memory` measures a process's resident
  memory against the **host's** total memory and says so in its evidence (`memory 6.00 GiB, 38%
  of host memory 16.00 GiB`); a cgroup's memory limit is not read, so inside a container place
  the share is still of the host (#307). `restarting` reads the service manager's restart
  counter; `ono.service/1` gains `restarts` (#209, ADR-0978).
- **A stated `COLUMNS` is the width of every view**, on a terminal and redirected alike
  (#209, ADR-0979).
- **The startup horizon does not wait for a slow provider.** It waits 150 ms, shows a count that
  has not arrived as `unknown — still being read`, and the late answer is there for the next
  view (#210, ADR-0982).
- **The link map states a round trip, a last seen and a shared host.** `look` at the local root
  prints the links; two links that reach one machine name each other in `same_host_as`
  (#213, ADR-0985).
- **`find place` answers a canonical space by name**, so `find place compute | take 1 | enter`
  works (#205, ADR-0965).
- **`enter <target>` yields the frame it pushed**, as its contract declared (#290, ADR-0963).
- **The trail names a file by its path**, in the `<type>/<key>` form `jump` resolves (#208).
- **A control group is called by its path** and never answers to a unit's name, so
  `enter <unit>.service` means the service (ADR-0971, 9246cbec).

## Cheaper answers

- **A `where` hands the provider the comparisons it declared.** A provider states which fields
  and operators it can decide at the source; a `where` directly after the producer offers its
  leading field-against-literal conjuncts and decides them again on what comes back. The journal
  declares `priority` and asks `journalctl --priority`; `explain` names what was handed over; the
  setting `providers.pushdown` turns it off. Over a generated journal: 5,000 entries 565 ms →
  71 ms, 200,000 entries 18.8 s → 142 ms (#281, ADR-0980). The journal reads `PRIORITY` only as
  one of the digits `0`–`7`, the texts journald's `--priority` matches on, so the handover never
  changes which records a `where` keeps (ADR-0988).
- **One object is asked for where one is named.** `trace process <pid>` reads the tree from the
  kernel's children lists and asks the provider for those pids; a `<type>/<key>` selector asks
  for the object it names. With 2,330 processes: `trace process <pid> --depth 1` 0.47 s → 0.11 s,
  `enter process/<pid>` 1.16 s → 0.14 s (#296, ADR-0986).
- **An observation asks every target at once** (#179, ADR-0970), **the edges of an object place
  are recalled inside their lifetime** (#216, ADR-0977), and **a selector sweep tells the service
  manager the name it is looking for** (ADR-0987). Together they take a selector miss at
  Profile M from 988 ms to 577 ms p95 — **still above #187's 250 ms target**, which this release
  does not meet.

## Jobs, from the maintenance prelude

Closed on `implementation` between v0.6.3 and this milestone, and released here:

- **Every backgrounded line is a job with an evaluator of its own**, native-only lines included,
  and `fg %N` collects it once with its status (#301, ADR-0958).
- **A job's relative paths mean the directory it was started in, and a plan acts on the absolute
  path it froze** (#302, ADR-0957).
- **Every job ends with the shell** — `SIGTERM`, then `SIGKILL` after one bounded grace period
  (#303, ADR-0959).
- **What a job keeps is bounded by `limits.command_capture_bytes`** (ADR-0958), and **a decimal
  number in JSON reads as the nearest `f64`** (ADR-0961).

## Contracts the repository checks

- **The conformance suite runs `conditional` commands that vouch for an example.**
  `unprivileged_examples` marks an example that needs no privilege; ten reads now run that were
  unchecked — `get file`, `get socket`, `trace user` among them (#295, ADR-0967).
- **The privileged paths run in the container.** Acceptance cases run as root for the account
  mutations (#220, case 130), a package hold (#221, case 131) and the container and namespace
  boundaries (#211, case 144); the plan-time `E0911` refusal has its case (#217, case 082); and a
  real accepted loopback connection proves `socket.accepts_connection` (#202).

## Deferred and not met

The milestone's inventory is unchanged: its 25 issues are in the table below. At the release
boundary each part that was not delivered was either kept as an open issue or rejected by an
ADR, so nothing the milestone asked for leaves the tracker.

- **#187 — selector-miss latency: not met, kept open as debt.** Profile M p95 576.7 ms (release
  build, 20 iterations) against 987.9 ms in the v0.6.2 baseline and a 250 ms target. On a quiet
  host without the profile's population a miss costs 0.17 s; the rest is the sweep enumerating
  every process's descriptors to find socket owners, for which procfs has no lookup by name. #187
  leaves the milestone and stays open for triage.
- **#209 — landmark and map gaps: closed; two remainders split out.** "Unusually high traffic"
  has no rule because no provider states a rate (#306); `high_memory` measures against the host
  and says so, and a cgroup's memory limit as its budget is #307.
- **#213 — the link map: closed; three remainders in `v0.6.6`.** A live latency needs a probe
  frame in the link protocol (#308); two-sided cross-host correlation (#309); a second hop on
  `map links` (#310). A hierarchy neighbour's null `confidence` stays, by spec §2.6.
- **#221 — container gaps: closed.** Its `trace container` edges and its root package case are
  delivered; `enter container` as an execution context is **rejected** by ADR-0114 and ADR-0968
  — a frame that ran commands inside the container while reading the host would act on state the
  user cannot see (spec §14.3). `enter container` narrows what later commands ask for, and
  nothing in this release enters a container's namespaces.

## Compatibility

Nothing a correct v0.6.3 configuration or script relies on was removed. `docs/MIGRATION.md` §14
lists what can look different: compiled KUANG/11 components need one `kuang-compile`; a job's
relative paths and a plan's frozen path; `enter <unit>.service` means the service and a cgroup is
named by its path; a redirected view follows a stated `COLUMNS`; `look` at the local root prints
the links; object places carry scope markers and crossing one prints a diagnostic line; the
startup horizon can show a count as still being read; `ono.kernel/1`, `ono.service/1`,
`ono.container/1`, `ono.process/1` and `ono.link-place/1` gained fields; a `high_memory`
landmark's evidence names the host's memory; a journal entry whose `PRIORITY` is not one digit
`0`–`7` is reported as `E0908` where v0.6.3 read it as a number; and such an entry, or one
without `PRIORITY`, is left out instead of reported when a `where` hands a priority ceiling to
the journal.

## Install

The `.deb` and `.rpm` for both architectures are on the release page:

```bash
sudo apt install ./ono_0.6.4_amd64.deb          # or ono_0.6.4_arm64.deb
sudo dnf install ./ono-0.6.4-1.x86_64.rpm       # or ono-0.6.4-1.aarch64.rpm

chsh -s /usr/bin/ono                             # make it your login shell
```

Verify before you install, in this order — the signature over the manifest first, the artifacts
against the manifest second. The sequence is the one in `docs/reference/release-verification.md`
and the README, and `scripts/verify-release.sh --dir <dir>` runs it on a download directory:

```bash
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github\.com/godspeed-you/ono-sendai/\.github/workflows/release\.yml@refs/tags/v' \
  SHA256SUMS
sha256sum --check --strict --ignore-missing SHA256SUMS
```
