# Ono-Sendai v0.6.1 — what v0.6.0 already did, done as one piece

A stabilization and polish release on top of v0.6.0. It adds no new capability. It takes things the
shell already did in two ways, or halfway, or only where a newline happened to help, and makes
them behave as one design. `docs/specs/ono_sendai_shell_spec_v0.6.1_stabilization_polish.md` is the
specification, and the GitHub milestone `v0.6.1` is its inventory: eight issues, all closed here.

> Make what already exists behave as though it was designed as one coherent system.

## Completion follows the expression you are typing

Tab after `where` offered the fields of the stream, and that was the end of it. One word later
the working directory's file names came back, offered with confidence at a position where no
file name can stand. Completion now reads a predicate the way the grammar does, from the same
tokens the parser and the highlighter use.

- **Field, operator, value, connector.** After a field come the comparisons its declared type
  supports: ordering for sizes, durations, numbers, instants and enums, `~=` for text, equality
  for a bool. After a whole comparison come `and` and `or`, and after those the fields again.
  `size>1GB` completes exactly as `size > 1GB` does. (#134)
- **Values the type already knows.** After `==` on an enum field its declared variants, found in
  any case, so `ESTA` completes to `established`; `true` and `false` for a bool; after a number
  compared with a size or a duration, that dimension's units: `where size > 5<Tab>` lists `5GiB`
  among the rest. After `in`, the opening `[`, and inside it the same values. (#135)
- **A file name only where a path can stand.** Inside a predicate Tab never reads the disk; if
  nothing is known, it offers nothing. Paths still complete for `get file`, for `cd` and for the
  arguments of programs. (#133)
- **Every candidate says what it is.** The second Tab lists each field, operator and unit beside
  its one-line doc, from the schemas and from the language contract, trimmed to the terminal's
  width. What gets inserted is the candidate alone. (#136)

One table decides which comparisons a field type offers, and a test evaluates every pair it names,
so completion can only suggest what the evaluator runs (ADR-0860).

## The prompt keeps what a program printed

`curl ifconfig.me` and `printf abc` print no final newline, and the next prompt erased their
output as it drew itself. The prompt now starts on a fresh line whenever the cursor is not at the
start of one, the way bash, zsh and fish do, and output that ended in a newline gains no extra
blank line. The shell asks the terminal where its cursor is once per prompt, never while you
type, and a terminal that does not answer is not asked again. (#132, ADR-0855)

## A contributed target answers the same way from anywhere

A target contributed by an installed plugin worked typed at the prompt and through an alias, and
failed with `resolve.command_not_found` from inside a function. A function body now reaches it by
the same route the prompt takes, loading a lazy package at first use. (#130)

## A permission shows the scope it holds

`set permission kubernetes kubeconfig-read --scope paths=~/elsewhere.yaml` replaces the declared
paths, as it always has, and now says so on the line: the notice names every path it dropped and
shows how to keep them. `get permission` shows a `custom` permission with the scope stored in
`policy.yaml` and enforced by the broker, where it used to repeat the declared one. `help set
permission` describes `--scope` for install permissions too. (#128, ADR-0857)

## `ss` keeps every socket it can read

Without a type flag `ss` also lists ICMP sockets, and a single `icmp6` line made the adapter reject
the whole output. Every other socket went with it. `icmp` and `icmp6` sockets now decode with
their own protocol, `icmp6` as `inet6`. A socket type the adapter does not know decodes as protocol
`unknown` with a `null` family and keeps the name `ss` printed in the record's adapter details, so
`where protocol == tcp` keeps comparing against a closed set. The rest of the output reaches the
pipeline intact. `ono.socket/1` widens accordingly: two more protocols, and a family that may be
unknown. (#131, ADR-0854)

## Compatibility

Nothing a v0.6.0 configuration, script or plugin relies on changes. `--scope` keeps its replacing
meaning; the notice goes to standard error. A `custom` row of `get permission` now names the
stored scope, which is the value it always should have shown. `ono.permission/1` and every other
schema keep their fields.

## Install

The `.deb` and `.rpm` for both architectures are on the release page. To install and make it your
login shell as an unprivileged user:

```bash
sudo apt install ./ono_0.6.1_amd64.deb          # or ono_0.6.1_arm64.deb
sudo dnf install ./ono-0.6.1-1.x86_64.rpm       # or ono-0.6.1-1.aarch64.rpm

chsh -s /usr/bin/ono                             # make it your login shell
```

Verify before you install — the sequence is in `docs/reference/release-verification.md` and in the
README, and it is the one `scripts/verify-release.sh` runs, byte for byte:

```bash
sha256sum -c SHA256SUMS --ignore-missing
cosign verify-blob SHA256SUMS --signature SHA256SUMS.sig --certificate SHA256SUMS.pem \
  --certificate-identity-regexp '^https://github\.com/godspeed-you/ono-sendai/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Or build it: `cargo build --release -p ono-cli`. See the README for configuration, the plugin
layout and login-shell setup.
