# Ono-Sendai v0.4.4 — a plugin can be signed by nobody's key

A patch release on top of v0.4.3. It closes a gap that release opened: `install plugin kubernetes`
became the whole ceremony, and publishing a plugin still asked somebody to keep a private key for
ever. Ono has not asked that of itself since v0.4.1, and now it does not ask it of a plugin
publisher either.

> Valid and trusted are two questions. They stay two answers.

## Signing without key custody

Ono signs its own releases keylessly: the release workflow holds no secret, proves its identity
with a short-lived token, and a verifier checks *which workflow on which tag* signed rather than
which key. KUANG/11 packages were specified the other way — ed25519 with a key file — which is a
good mechanism with one consequence nobody wanted.

- **A package may carry `signature.sigstore.json`** beside its manifest: a Sigstore bundle over
  exactly the bytes the ed25519 signature covers, the package's own description. A package may
  carry either form or both, and where both are present both must verify. Neither signature is
  part of what a signature covers.
- **Verification is offline**, against certificate authorities and transparency-log keys this
  build carries, and in this order: the bundle must vouch for the description recomputed from the
  package on disk; the certificate must chain to one of those authorities for code signing; its
  key must have made the signature; the log's own signed timestamp must verify and must fall
  inside the certificate's ten-minute life, which is what pins a signature to the run that made
  it; and the subject and issuer are read out.
- **The trust store enrols an identity beside a key.** `trust.yaml` gains `identities:` — a
  publisher, an OpenID issuer and a subject, where the subject may end in one `*` so a
  repository's releases are enrolled once rather than once per tag. `revoked` works there as it
  does for a key, and a revocation of either wins.
- **Nothing is trusted by being valid.** A bundle that verifies under an identity nobody enrolled
  is `signature: valid`, `trust: unknown`, exactly as an ed25519 signature from an unenrolled key
  is.

What is deliberately not checked — the certificate transparency SCT and the Merkle inclusion proof
against a signed checkpoint — is named in ADR-0609 rather than left to be discovered.

The verifier is narrow and lives on the host side, built on `ring` and `rustls-webpki` from the
existing graph plus `x509-parser` for the two certificate fields webpki does not expose. It is
proven against a real bundle: the one this project's own v0.4.3 release published over its
`SHA256SUMS`, with the tampering cases refused.

## Beside it

- **The licences of every crate the binary links ship with the binary** (ADR-0608, released in
  v0.4.3 and unmentioned in its note). `THIRD-PARTY-LICENSES` is generated from `Cargo.lock`, held
  to it by `spec-check`, and installed beside `LICENSE` in both packages: 311 crates, 173 distinct
  documents each reproduced once, and the crates that ship none named rather than passed over.

## Compatibility

Nothing changes for an existing package. `kuang-sign` works unchanged, a signed package keeps
verifying, and no installed package needs re-signing. `kuang-sign` gains `describe`, which writes
the bytes a signature covers so something other than it can sign them.

A package signed *only* keylessly needs this release: v0.4.3 does not know the bundle file, reads
such a package as unsigned, and computes a different content digest for it. A publisher moving to
keyless signing should require `ono >= 0.4.4`.

## Install

The `.deb` and `.rpm` for both architectures are on the release page. To install and make it your
login shell as an unprivileged user:

```bash
sudo apt install ./ono_0.4.4_amd64.deb          # or ono_0.4.4_arm64.deb
sudo dnf install ./ono-0.4.4-1.x86_64.rpm       # or ono-0.4.4-1.aarch64.rpm

chsh -s /usr/bin/ono                             # make it your login shell
```

Verify before you install — the sequence is in `docs/reference/release-verification.md` and in the
README, and it is the one `scripts/verify-release.sh` runs, byte for byte:

```bash
sha256sum -c SHA256SUMS --ignore-missing
cosign verify-blob SHA256SUMS --signature SHA256SUMS.sig --certificate SHA256SUMS.pem \
  --certificate-identity-regexp '^https://github\.com/godspeed-you/ono-sendai/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Or build it: `cargo build --release -p ono-cli`. See the README for configuration, the plugin
layout and login-shell setup.
