# Ono-Sendai v0.5.0 — time as a coordinate, and evidence as the limit of what may be said

`docs/ACCEPTANCE.md` §4.11 is this tranche's definition of done, derived from the specification's
own forty-seven acceptance scenarios, its performance evidence, its twenty core invariants and its
twenty-three release criteria. Every one of its 120 boxes is ticked, and every tick names an
automated proof that runs in the gate or in the acceptance container. §66.9 permits an open box
only as a recorded exclusion; the two this tranche records are `M` and `C` in the full-screen
timeline, and ADR-0781 is where they are written down. A reader learns what is unfinished here or
nowhere.

`docs/specs/ono_sendai_shell_spec_v0.5_temporal_causal_systems_interface.md` is the specification.

> Space made the machine explorable. Time makes it alive — as far as the evidence reaches, and
> no further.

## What the tranche is

v0.4 gave the session a place. v0.5 gives it an instant. `at -10m` moves the temporal coordinate
and leaves the spatial one alone; `now` comes back. Between those two words sit an evidence
ledger, a reconstruction engine, a timeline, a `changes` engine and a causal engine, and one rule
that governs all of them: Ono reconstructs only what its evidence supports, and a nearby event is
never promoted to a cause.

Three decisions the specification could not make for itself are recorded as ADRs, because each
collides with something already shipped:

- **ADR-0610** — v0.5 §34 numbers the temporal error family E1101–E1114, and v0.4.1 §21.4 had
  already spent the first three of those on the resource family. The names §34 fixes are kept
  exactly; the codes take E1301–E1314, the lowest free block. A reader holding §34 open adds two
  hundred.
- **ADR-0611** — v0.5 §35 asks for `ono.evidence/1`, which v0.2 §31.24 already holds and which
  carries an unrelated record. The temporal one is registered as `ono.temporal-evidence/1`.
- **ADR-0612** — the six crates of §39, their places in the layering, and the reference store.

Eleven more were written while the tranche was being proved, and each of them changed behaviour
rather than recording a naming decision:

- **ADR-0613** — §9.4's temporal metadata on a reconstructed object rides the reserved `ono.temporal`
  extension key rather than becoming a declared field on twenty-three schemas, so a pipeline
  written against the present still parses the past.
- **ADR-0775** — `look`'s change section reports an absence only where coverage supports it. A
  ledger that observed nothing over the window answers `unknown` with no source, never `empty`:
  §24.3 forbids a change summary generated from a source that was not watching, and a
  session-only ledger is `partial` by §8.3 and can prove no absence at all.
- **ADR-0776** — a time-bounded question walks time rather than sorting a place. A third index,
  a store version, and the two §32.3 budgets that were missed before it.
- **ADR-0777** — the shell runs the recorder, and what it observes becomes history. §10.7 makes the
  session's own ledger evidence for as long as the session has been alive, so observation starts
  when the session starts rather than when the first temporal command happens to be dispatched.
- **ADR-0778** — `timeline` is a stream of `ono.temporal-event/1` and its window is a rendering.
  §11.4 makes the answer pipeline-compatible; the window, the evidence and the coverage are a line
  the renderer adds, never the data contract (§2 invariant 19).
- **ADR-0779** — one coordinate is one wall clock, and a live map has a ledger of its own. §25.3's
  HUD reads local time, and the cursor a paused map carries is backed by the historical ledger
  rather than by whatever the live view happened to hold.
- **ADR-0780** — a historical `get` is answered by a temporal seam in front of every provider, so
  §9.6's historical collections and §55.9's "past mode that is only cosmetic" are settled in one
  place instead of twenty-three.
- **ADR-0781** — the full-screen timeline is one view behind two doors: `timeline --view` and the
  rewind key. `M` (map at event time) and `C` (copy the reference) are recorded exclusions.
- **ADR-0782** — one Ctrl-C belongs to the line, not to the first pipeline that looks. The
  interrupt note is latched for the length of the line instead of being consumed by whichever
  `each` item started next, and a synchronous ledger scan asks every 256 rows whether anybody still
  wants the answer (§32.6).
- **ADR-0783** — a printed event reference is unique in the ledger, not in the session. §11.6 makes
  a rendered reference "usable in subsequent commands", and a later shell resolves it against the
  whole store, so the prefix is minted long enough to name one event there — six to nine hex digits
  against the §49 fixture — with a digit of headroom for what the printing session records next.
- **ADR-0786** — `temporal.out_of_retention` is a fact about what a store held, not about what its
  policy allows. §34 words it "known to have expired", so a recorder started this morning answers
  `at -3d` with §12.3's `temporal.not_recorded` and the reach of each source, rather than claiming
  three days of history expired that it never had.

Two more were written against the layers beneath, because the tranche made their defects legible:

- **ADR-0784** — a namespace the kernel will not name is a refusal, not an absence. `/proc/1/ns` is
  unreadable to an ordinary user and `readlink` there succeeds while disclosing nothing; the group
  now reports `permission_denied` where v0.4 §35.2 wants it instead of the false `empty` of §35.3.
- **ADR-0785** — a tranche freezes its own baseline snapshot and never edits an earlier one.
  `docs/baselines/` is a register with one file per tranche, so v0.5's nine measurements are frozen
  in `v0.5.0.json` rather than backdated into the v0.4.1 snapshot.

## Structure

Six crates, as §39 fixes them:

- `ono-temporal-core` — the canonical vocabulary: event, evidence, coverage, gap, causal link,
  time selector, temporal context, and the ledger contract itself. It names no SQL.
- `ono-temporal-ledger` — the bounded in-memory ledger and the SQLite WAL store beneath it, with
  migrations, retention, integrity and source-sequence continuity.
- `ono-temporal-reconstruct` — checkpoints, event replay, coverage composition, gap propagation.
- `ono-temporal-query` — timeline, changes, event search, causal planning, relevance.
- `ono-temporal-render` — presentation only. It depends on `ono-value` and on nothing else, so
  §39.3's rule that a renderer reaches no provider, ledger or network is a fact about the
  dependency graph rather than a habit.
- `ono-recorder` — the user-level, opt-in, bounded collection service.

`ono-cli` parses, dispatches, and owns the active temporal context. It is not the engine.

## What it costs

Measured against §49's fixture — a real store of 1,000,000 events, 400,000 evidence records,
10,000 action records and 288 checkpoints over 100,000 objects and 500,000 relation changes,
1,820.7 MiB on disk, built deterministically from seed 327753 in 319.9 s, digest `b67d6b28…` — in
a release build, twenty iterations, one process per sample:

| §49 / §32.3 row | measured p95 | budget |
|---|---|---|
| `temporal.startup_disabled` | 6.5 ms | 5 ms *added* to a 7.1 ms cold start |
| `temporal.recorder_idle` | 10.6 ms | §32.4 states no latency budget |
| `temporal.timeline_15m` | 6.6 ms | 100 ms |
| `temporal.changes_1h` | 39.3 ms | 150 ms |
| `temporal.reconstruct_recent` | 57.0 ms | 150 ms |
| `temporal.map_historical_l1` | 0.2 ms | 150 ms |
| `temporal.why` | 1.9 ms | 200 ms |
| `temporal.find_event` | 36.2 ms | 150 ms |
| `temporal.retention_sweep` | 3.4 s over 2,887 evictions | §31.8 asks for bounded background work, not a deadline |

`temporal.startup_disabled` is the one row stated as an increase rather than a ceiling: §32.1 says
v0.5 "MUST add less than 5 ms p95 to Ono interactive startup", so a budget compared against an
absolute figure would pass while saying nothing. The row names `shell.cold_start` and the verdict
subtracts (ADR-0748). The two figures are 6.5 ms and 7.1 ms measured in the same run, so the
tranche adds nothing measurable to a shell that is not recording — which is what §32.1's laziness
requirement is for.

Two of those rows missed before ADR-0776 — `why` at 227.8 ms and `reconstruct_recent` at 198.5 ms
— and both missed for the same reason: a scope is a prefix range, an index led by a range gives no
usable order, and SQLite was sorting every event of a place to answer a question about a hundred of
them. The fix is an index that leads on the instant, and the cost model it produces is one a reader
can predict: a question that names an instant or a count costs the window or the count, and a
question that names neither costs the place.

## Nothing is left unproven

Every box of `docs/ACCEPTANCE.md` §4.11 is ticked, and each is ticked by a named automated
proof — a test that runs un-ignored in the gate, or a case that runs in the acceptance
container. `xtask/tests/temporal_evidence.rs` resolves every one of them against the tree on
every gate run, so a proof that stopped existing turns the gate red rather than leaving a
box ticked by nothing.
