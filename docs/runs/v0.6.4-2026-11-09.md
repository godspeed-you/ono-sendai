## What the verification pass found

- **A regression of the run's own.** ADR-0986's keyed lookup absorbed `process/<pid>` before the
  session had learned its own pid namespace, so entering a process in another namespace announced
  no crossing. Acceptance case 144 caught it in the container — no unit test can make a pid
  namespace on this host — and `93c9a007` fixes it.
- **Two cases that never ran before they were committed.** Case 141's fixture was drawn on the map
  it was meant to be missing from, and its terminal had no size; the boundary case shared the
  number 140 with the plugin signature case and became 144.
- **Earlier in the run:** a remembered engine refusal shown on a process that never asked
  (`44b2cbbd`), configured `spatial.*` settings ignored when `enter <target>` created the session
  (`a514c04d`), `enter <unit>.service` ambiguous between the service and its cgroup (`9246cbec`),
  and case 103 asserting `unsupported` on an exit this release made answerable.
- **CI** was red on the stale binary-size record and on case 103 until those were corrected.

### What the release review found

One read-only Opus reviewer read the riskiest parts of `41cc0f31..2e4eb29e` (pushdown, journal
priority, namespace and container boundaries, `high_memory`, schemas, dependencies) and the run's
*Found* list. Two defects were fixed, each test-first:

- **Release-blocking:** the journal read `PRIORITY` texts `03`, `+2`, `-1` as numbers; journald's
  `--priority` matches the exact digits, so the handover of ADR-0980 changed which records a
  `where` kept, silently. 20444562, ADR-0988.
- **Misleading text:** `high_memory`'s evidence did not say its budget was the host's. 6420a243.

Notes kept, not changed: `ono.link-place/1.same_host_as` is a non-nullable field Ono's own map
always fills (MIGRATION §14 says so); `ono.log-record/1`'s level/priority sentences contradict
each other (STATE). Every *Found during the v0.6.4 run* entry was classified safely deferred.
