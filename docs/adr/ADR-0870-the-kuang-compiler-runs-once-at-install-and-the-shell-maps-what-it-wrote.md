# ADR-0870: The KUANG/11 compiler runs once, at install, and the shell maps what it wrote

- Status: accepted
- Date: 2026-09-24
- Spec refs: §31.10, §31.11, §31.36, §31.79, §43; K11P §12, §20; K11A §8.2, §16; ADR-0007, ADR-0283, ADR-0311, ADR-0522, ADR-0569, ADR-0602, ADR-0863 (§3)
- Decided by: agent (autonomous)

## Context

Issue #126. ADR-0863 §3 (the size record that measured the binary) decided that the KUANG/11
compiler leaves the shell: a package keeps shipping `runtime/component.wasm` (§31.36), the
SDK's own tool compiles it once on the installing machine, the shell links wasmtime's runtime
without Cranelift and refuses a component whose compiled artifact is missing or was written by
another engine, naming the tool. Until now `ono-kuang-supervisor` called `Component::from_file`,
which compiles on every load, and the workspace linked wasmtime with `cranelift` and
`parallel-compilation` into `ono`.

ADR-0863 left three things to this record: where the artifacts live and who may write there, the
reason `Component::deserialize_file` — an `unsafe` API — is sound here, and what invalidates an
artifact. Implementing it showed that two of its sentences cannot be taken literally, and this
record says so where it applies.

## Decision

**1. `ono` links the runtime only.** The workspace declares wasmtime with `runtime`,
`component-model`, `async` and `std`; `wasmtime-wasi` adds nothing that compiles. Cranelift and
`parallel-compilation` are behind `ono-kuang-supervisor`'s `compiler` feature, which only
`ono-kuang-sdk` enables, for its `kuang-compile` binary; the SDK takes the supervisor only off
`wasm32`, so a plugin built for WebAssembly is untouched. `cargo tree -p ono-cli -i
cranelift-codegen` finds no such package. Winch is also a compiler and is not linked; Pulley's
interpreter is part of wasmtime's `runtime` feature and stays.

Cargo unifies features across the packages of one invocation, so the build that proves this
builds `ono-cli` **alone**: `docker/Dockerfile` builds and installs `ono` before it builds the SDK
and `xtask`, and `scripts/package.sh` already builds `--package ono-cli` alone. A workspace test
build (`cargo test --workspace`) still links Cranelift into the `ono` it tests, harmlessly: the
shell never calls the compiler, so the load path it exercises is the same one.

**2. `kuang-compile` sits beside `kuang-sign` in the SDK.**
`kuang-compile [--store <directory>] <component.wasm>...` compiles each component with the
supervisor's own engine configuration — there is one `engine()`, and an artifact only loads into
an engine configured like the one that wrote it — and prints the artifact's path. It is
idempotent: compiling the same bytes again replaces the artifact.

**3. Artifacts live in artifact stores, named by the component's digest — never in the package.**
An artifact is `<store>/<sha256 of the component's bytes>.cwasm`. The shell looks in, in order:

| store | written by | default path |
|---|---|---|
| the operator's | `kuang-compile`, run by `install plugin` or by hand | `$XDG_CACHE_HOME/ono/kuang/compiled/`, else `~/.cache/ono/kuang/compiled/` |
| the system's | an administrator, an image build, a distribution: `kuang-compile --store …` as root | `/usr/lib/ono-sendai/kuang-compiled/`, beside K11A §8.2's `plugin-sources/` |

The first store whose artifact loads wins. A refused artifact does not end the search — a stale
one in the operator's store must not hide a current one the system provides — and when none
loads, the first refusal is the answer, and `missing` only when no store had one.

This departs from ADR-0863's "writes the engine's own `.cwasm` beside it", for two reasons found
in the code rather than preferred:

- `artifact_files` (ADR-0311) is *every file under the package directory*, and both the content
  digest an install pins and every signature cover it. A `.cwasm` written beside the component
  would change the digest the load re-verifies (`lifecycle.v1` `load` requires it) and invalidate
  the publisher's signature.
- A compiled artifact is native code the shell maps into its own address space. If one could sit
  in the package directory, a publisher could ship one, and every confinement the component tier
  gives (ADR-0569) would be one file away from void. An artifact is found by the digest of the
  bytes it was compiled from, in a store no package writes, or not at all.

Naming by digest is also what makes a package upgrade invalidate the artifact: new bytes, new
name, `missing`. A cache in the XDG sense is the right home — everything in it is regenerated by
one command — and losing it costs that command, which the refusal names.

**4. Who may write a store is checked, not assumed.** Before mapping, the shell requires the
artifact and the directory holding it to belong to the user it runs as or to root, and to be
writable by nobody else (`mode & 0o022 == 0`); otherwise the refusal's reason is `untrusted` and
nothing is mapped. `kuang-compile` creates the store `0755` and the artifact `0644` whatever the
umask, writes beside the final name and renames into place, and refuses to write into a store
the shell would refuse to read.

**5. The refusal is `load.component_not_compiled`, `Ono-Sendai-K11105`, kind `resolution`**
(contract first: `docs/contracts/errors.yaml`, `docs/contracts/kuang/errors.v1.yaml`, the `load`
and `install` transitions of `lifecycle.v1.yaml`). §31.79's `load.*` family has no name for it:
`load.runtime_unavailable` is a policy answer about a tier, and this is a missing local artifact
with a command as its remedy. The metadata carries `reason` (`missing`, `incompatible`,
`untrusted`), `component`, `artifact`, `engine` (`wasmtime <version> on <arch>`) and `command`,
the exact `kuang-compile <component>` to run; the message says the same in words, and for
`incompatible` it carries wasmtime's own reason (`incompatible version`, `compiled for
architecture`, `failed to parse precompiled artifact as an ELF`, …).

**6. `install plugin` runs the compile step.** In the install transaction (ADR-0602), after the
package is staged and before it is placed, a `wasm-component` package's staged component is
handed to `kuang-compile` — the one beside the running `ono`, else the first on `PATH`. A
component the tool refuses, or a tool that is not there, refuses the install with
`load.component_not_compiled` and leaves nothing placed. The artifact written for a transaction
that later fails stays in the operator's store and is inert: it is only ever found by the bytes
it was compiled from. An upgrade is an install, so it compiles too. Trusting a publisher
(`trust.yaml`, ADR-0312) changes no bytes and needs nothing compiled.

**7. The `unsafe`.** `Component::deserialize_file` is `unsafe` because what it maps runs as
native code; wasmtime cannot tell an artifact it wrote from one crafted to look like it. The
call is one function in `ono-kuang-supervisor/src/compiled.rs`, under
`#[allow(unsafe_code, reason = …)]` and a `// SAFETY:` comment, and the argument is:

- the only writer of a store is `kuang-compile`, which compiles with this crate's engine
  configuration from a component the operator installed;
- §4's check has just refused any artifact or store someone other than this user or root could
  have written, and no package can put an artifact where the shell looks (§3);
- before it maps a byte, wasmtime itself refuses a file that is not an ELF artifact of its own,
  was written for a module rather than a component, or carries another engine version, another
  architecture or operating system, or other compilation settings, tunables or wasm features —
  which is how a stale, foreign or damaged header ends as a structured refusal and not as a crash;
- an artifact is replaced by rename, so a mapped file is never written under the mapping.

What it does not cover, stated so nobody assumes it: wasmtime does not checksum the machine code.
A bit flipped inside `.text` of a correctly owned artifact is executed as it is — the same trust
a user gives any executable in a directory only they can write. Recompiling repairs it.

ADR-0863 calls this "the workspace's first `#[allow(unsafe_code)]`". It is not:
`ono-kuang-supervisor` already holds `unsafe` for the confinement syscalls of ADR-0283 and
ADR-0443, under the same attribute, and is in the sanitizer jobs of ADR-0522 already. The crates
that are `#![forbid(unsafe_code)]`, `ono-cli` among them, stay so.

**8. An artifact is per engine version and per architecture.** wasmtime stamps its major
version into every artifact and checks it, with the target, on every map. A shell upgrade that
moves wasmtime to another major version therefore turns every artifact on the machine into an
`incompatible` refusal naming `kuang-compile`, one command per component; a package upgrade turns
its own into `missing`. Versions within one major are compatible by wasmtime's own contract, and
the flag, tunable and feature checks still run.

**9. The image compiles the example where it builds it.** `docker/Dockerfile` copies
`kuang-compile` beside `ono` and runs `kuang-compile --store /usr/lib/ono-sendai/kuang-compiled
/usr/local/lib/kuang-example-plugin.wasm` as root, so case 214, which places the component by hand,
passes unchanged. Cases 350–352 prove the refusal (missing and stale), the step fixing it, and
`install plugin` producing the artifact, against the real binary.

## Consequences

Easy: the stripped `ono` loses Cranelift, and with it about a quarter of its size. Measured on
this tree with
`cargo build --release --locked -p ono-cli` and `stat -c %s` (toolchain 1.94, lld):

| release profile | before (fe1508dc) | after |
|---|---|---|
| today's (`opt-level = 3`, thin LTO) | 46,094,688 B | 35,468,160 B (−10.6 MB, −23 %) |
| #124's (`opt-level = "s"`, fat LTO), by environment override | 28,736,736 B | 22,153,824 B (−6.6 MB, −23 %) |

Also easy: a component loads without compiling, so `load plugin` on a component is a map rather
than a compile.

Hard: a component package is now bytes plus an artifact somewhere else, and after a shell
upgrade every component needs `kuang-compile` once. The refusal names the command and the tool is
idempotent, so the cost is one command per component per engine version.

Hard, and open: **the distribution packages ship `ono` only.** `scripts/package.sh` and the
`.deb`/`.rpm` assets carry neither `kuang-sign` nor `kuang-compile`, so a shell installed from
them refuses to install a component package, naming the tool, until the tool ships beside it or
is built from the SDK. Shipping it is a packaging change of its own (it puts the compiler back
into the package, if not into the binary) and is left to that increment.

Also open: `THIRD-PARTY-LICENSES` is generated from the workspace's resolved graph, in which
features are unified across members, so it still lists Cranelift's crates although `ono` no
longer links them. That over-states what the binary contains and understates nothing.

Tests: `crates/ono-kuang-sdk/tests/compiled.rs` (missing, changed component, stale engine
version, foreign architecture, truncated and garbled artifacts, an artifact or store others can
write, the tool's own refusals, owner-only modes); the wasm-tier cases of
`crates/ono-kuang-sdk/tests/conformance.rs`, now compiled through `kuang-compile`;
`crates/ono-cli/tests/plugins.rs` (the refusal through the shell, `install plugin` compiling,
an uncompilable component refusing the install); acceptance cases 214 (unchanged), 350, 351, 352.

## Alternatives considered

- **The artifact beside the component, in the package directory** (ADR-0863's wording). Rejected
  for §3's two reasons: it breaks the digest and signature that cover every file of a package,
  and it lets a package carry native code the shell would map.
- **A store directory per engine version** (`…/compiled/wasmtime-47/`). Rejected: a stale
  artifact would become indistinguishable from a missing one, and wasmtime checks the version
  anyway. One name per component keeps "another engine wrote this" a refusal that says so.
- **A checksum beside each artifact.** Rejected: it defends against disk corruption, not against
  the writer the ownership check already excludes, and it would need a second file kept in step
  with the first under concurrent writers.
- **Winch or Pulley instead of Cranelift in the shell.** Winch is a compiler too, and running
  every component in the Pulley interpreter trades the size for throughput §34 budgets.
- **An environment variable naming the stores.** Not needed by any test or deployment: the
  operator's store follows XDG, and an administrator writes the system store with `--store`.
